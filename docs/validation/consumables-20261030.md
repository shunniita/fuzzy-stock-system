# 共通消耗品の数量表示と数量経路の限定検証

確認日時：2026-10-30 13:09:24 UTC。Node.js 24.21.0を使用。
基点：`dc6f098665f45cba5192a4a797ebac9a76dcfca3`。

共通消耗品は補充基準なしで数量だけを管理できる。今回の表示修正は、数が分かる在庫と残量区分だけの在庫が混在するとき、分かる分を「数量合計」ではなく「数量の数値部分の小計」と表示するもの。例えば、数えた0本と「少ない」の在庫があっても、全体の数を0本と断定しない。

## 再実行

リポジトリのルートで実行する。npm依存を追加せず、実際のTypeScriptソースと既存fixtureを読み込む。

```sh
node --test --test-reporter=tap scripts/test-consumables-subtotal.mjs
node --test --test-reporter=tap scripts/test-consumables-quantity-flow.mjs
```

スクリプトは自身の位置からソースとfixtureを解決する。別の作業ディレクトリから絶対パスで実行した場合も同じ対象を確認できる。

| 数量経路の検証 | 27 | 0 | 登録・使用・数え直し・保存と再読込・別の数量からのバックアップ復元 |

数量経路では、不正入力後の保存無変更、数が不明な在庫、過剰使用の保留、遡及使用の包含回答、残量区分の失効、書込み失敗と応答喪失後の再試行も確認した。古いsnapshotによる`core.commit`の競合拒否を確認しており、旧版アプリのwriterや共有保存の世代競合を実行した検証ではない。

スクリプトを含む5ファイルの`node --check`と`git diff --check`も成功した。構文確認は型チェックではない。

## この記録の限界

保存・復元はメモリ内の`StoreLike`を使うcore境界の確認。不正入力では例外と保存無変更を確認するが、例外種別や画面のエラー文言は固定していない。

このローカル検証ではVitest（変更した単体テストを含む）、完全な型チェック、ビルド、Windows E2E、配布検証は未実行。DOM送信、実ブラウザーでの永続保存、IndexedDB、SharedAuthorityの世代競合も未実行であり、39件の成功をそれらの成功として扱わない。追加のスクリプトは既存のnpmテストやCIへ組み込んでいない。
