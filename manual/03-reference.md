# 3. 画面と用語

[目次](README.md) · 前へ：[作業別ガイド](02-guide.md) · 次へ：[困ったとき](04-troubleshooting.md)

画面構成や用語の定義、上限、Excel出力のシート構成、記録の設計思想をまとめたリファレンスです。具体的な操作手順は[作業別ガイド](02-guide.md)を参照してください。

## 六つの行き先

初期設定の簡単操作モードでは、画面上部に「在庫と入力」「確認・履歴」「登録情報」「管理」が並びます。「管理」で高度な操作モードに切り替えると、「セット」と「不足・依頼・案件・用途」も選べます。

| 行き先 | 表示・操作できる内容 |
|---|---|
| 在庫と入力 | 在庫一覧の検索・絞り込み、保管単位の詳細・履歴の表示、すべての業務操作の入力 |
| セット | 製品別のセット（標準部品表）一覧と構成の確認、セットの登録、対象セットを固定した部品受け取り・必要明細生成・作業開始 |
| 不足・依頼・案件・用途 | 共通消耗品の集計、案件・用途別の必要数・不足・補充依頼・到着と割り当て、供給の履歴 |
| 確認・履歴 | 確認が必要な記録（要照合事項）の一覧と、台帳全体の履歴の検索 |
| 登録情報 | 品目・場所・案件・用途・担当者・工程・包装・補充基準の現在設定の確認 |
| 管理 | 復元用バックアップの保存・復元、閲覧用Excel出力、タブ終了後の入力回収の設定、練習用の台帳での初期化 |

画面幅が狭いときは「入力」区画が在庫一覧の下へ移ります。列数の多い表では表の枠内を横スクロールして右端まで確認できます。

「在庫一覧の絞り込み」にある品目・案件・用途・場所は一覧表示を絞る検索欄です。「入力」区画にある同名の欄が実際に記録される値になります。

## 入力するときの選択

### 作業の種類と操作の二段選択

高度な操作モードでは「作業の種類」で候補を絞り、「操作」で目的の操作を選ぶと入力欄が切り替わります。キーボード操作では目的の選択肢を選んだことを確認してから`Tab`キーで次の欄へ進みます。`Tab`キーだけでは選択内容は変わりません。

| 作業の種類 | 含まれる主な操作 |
|---|---|
| 現物の登録・使用・移動 | 現物の登録、使用、外へ出す、場所の移動、一部を分けて移動、分割、統合、案件・用途の付け替え、取り分けと解除 |
| 製造・工程 | 作業の開始、セットでの作業開始（材料の使用を推計）、作業終了、確認の完了、次の作業へ渡す、作業の中断と再開 |
| 工程の登録・設定 | 工程の登録、完了基準の変更、次工程の場所の指定・解除 |
| やり直し・修理 | やり直し・修理の開始、交換部品の使用、取り外し部品の廃棄・回収、返ってきた物の仮記録と割り当て |
| 必要な数・依頼・発注 | 必要な数の登録・改訂、セットから必要明細を生成、2つのセットでまとめて生成、生成した必要明細の変更、足りない分の記録、注文・購入予定の記録、注文の確定、返事・届く予定日の更新、依頼の取消 |
| 受け取り・割り当て・返却 | 受け取り、セットの登録・変更・削除、セットからのまとめて受け取り、既存受け取りへの割り当て、実際に受け取った数・割り当ての訂正、余った分の振り分け、返品の受付確認、開けた物の残り具合 |
| 数え直し・訂正・照合 | 数えて確認・訂正、数の食い違いのメモ、作業の状態の訂正、実際の日時の訂正、間違えた記録の取り消し、別記録からの後入力、確認事項を片付ける |
| 仮の記録・所属の整理 | 対象が分からない動きの仮記録、仮記録の割り当て、品目・案件・用途が不明な現物の整理 |
| 登録情報の登録・変更 | 品目・場所・案件・用途・担当者の登録、名称・品番・コード・利用停止・再開の変更、包装・入り数の設定、共通消耗品・補充基準の設定 |

### 操作の切替確認と切替拒否の条件

| 場面・状態 | 画面の動作 |
|---|---|
| 未保存の編集がある状態で別操作・別対象へ切り替える | 破棄の確認ダイアログが出る。キャンセルすると確認チェックや日時を含めて元の入力が保たれる |
| 未解消の更新競合があり照合が完了していない | 入力内容を保護するため切替を拒否し、入力欄の下部に理由を表示する |
| 保存結果不明、または一部だけ保存された状態が残っている | 同上（照会・再試行・確定が終わるまで切替不可） |
| 別画面で記録が保存され再読込待ち、または読込不能 | 同上（最新記録の読込や原因確認が終わるまで切替不可） |
| 保存処理の実行中 | 同上（完了するまで切替不可） |
| 確認チェック欄がある操作でプレビュー後に入力値を変えた | チェックが自動で外れる。変更後の内容で再プレビューし、もう一度チェックを入れてから記録する |

## 新しいIDを決める

保管単位のIDは現物の箱・袋・束・作業ロットなどを1つずつ区別する識別子です。同じ品目でも箱が2つあれば別のIDを付けます。品目の「品番・コード」とは別です。

| 場面 | IDの命名例 |
|---|---|
| 最初の箱を登録する | `P-01` |
| その箱から一部を分ける・別場所へ移す | `P-01-B` |
| 作業を始める製品ロットを記録する | `W-001` |
| そのうち作業が終わった分を記録する | `W-001-F1` |

IDの形式に固定の規則はありません。現場の通し番号などを自由に入力できます。空欄や空白だけのIDは使えません。使い切った箱や統合してなくなった箱を含め、同じ保存先で一度使ったIDは再利用できないため、「使用済み」と出た場合は別の新しいIDを付けます。

## 数量を読む

| 用語・表示 | 定義 | 例 |
|---|---|---|
| 保管単位 | 1つの箱・袋・束・作業ロットなど、ひとまとまりとして管理する現物 | `GUIDE-P-01`の箱 |
| 単位 | 数量を数える単位。異なる単位同士は直接加減算しない | `個`、`本`、`袋`、`箱`、`台` |
| 数えた | 現物を実際に数えたことに基づく数量 | 箱の中身を数えて`12`個 |
| 表示の数（ラベル・パッケージ） | 中身を数えず、外箱ラベルや納品書などの記載を採用した数量 | ラベル表記の`100`本 |
| だいたい | 目視やセットの標準値など、見積もり・推計に基づく数量 | およそ`80`本 |
| 数が不明 | 現時点で数値として分からない状態。**0ではない** | 中身未確認の開封箱 |
| 記録上の数 | 登録・受け取り・使用・移動などの記録から計算した現在数 | 12個から2個使って残り`10`個 |
| 確認が必要 | 後入力の包含未確認や記録間の矛盾など、人の確認を要する状態 | 数え直しより前の使用を後から入力した状態 |

**数が不明な場合は0ではありません。** 状況に応じて「数量の根拠」と「数量」を次のとおり組み合わせて記録します。

| 現物の状況 | 選ぶ「数量の根拠」 | 「数量」欄の入力 |
|---|---|---|
| 数えて空（0個）だと確認した | `数えた` | `0` |
| 数えて12個だと確認した | `数えた` | `12` |
| 目視で見積もるとほぼ残っていない | `だいたい` | `0`（または見積もり値） |
| まだ数えておらず数が分からない | `数が不明` | 空欄（入力しない） |

「数えた」を選んだまま数量を空欄にすると入力エラーになります。一方、数が分からないまま「数えた・0」で記録すると「数えて空箱だと確認した」という意味になり、不足や在庫の判断を誤らせます。数字だけでなく根拠も合わせて選んでください。

## 混同しやすい状態

| 表示・記録 | 意味と他の状態との違い |
|---|---|
| 必要な数 | 案件・用途で必要と登録または生成された数量。現物の確保を意味しない |
| 不足 | 必要な数に対して使用可能な在庫や使える到着分が足りない数。数量不明が含まれる場合は判定不能または候補表示になる |
| 依頼 | 補充や発注を依頼した記録。依頼しただけでは在庫数に加算されない |
| 未着 | 依頼した数のうち、まだ受け取りが割り当てられていない残数 |
| 実際に受け取った数 | 現場に届いた現物全体の数量 |
| 届いた数 | 受け取った現物のうち、特定の依頼の到着分として割り当てた数量 |
| 使える数 | 依頼への到着分のうち、不良などを除いて不足の解消に充てられる数量 |
| 取り分け | 不良・使用可否確認待ち・返却待ち・予備として、使用可能在庫から除外している状態。現物が消えたわけではない |
| 作業の状態 | `作業なし`、`作業中`、`確認待ち`、`完成（渡す前）`の区分。工程完了累計は過去に完了した延べ数であり、現在庫には足さない |

## 日時・名称・担当者

| 項目 | 仕様と扱い |
|---|---|
| 実際の日時 | 現場で実際に物が動いた日時（日本時間）。分からない場合は推測で埋めず「実際の日時が不明」を選ぶ |
| 入力した日時 | このソフトで「記録する」を押した日時。後入力では「実際の日時」と異なる値になる |
| 品番・コード | 品目・場所・案件・用途を識別するコード。先頭の`0`や記号も文字列としてそのまま保存される |
| 履歴の名称保持 | 履歴には記録当時の品目名・コード・工程名が残る。後から登録情報の名称を変えても過去履歴は書き換えず、旧履歴に当時の名称がない場合も現在名で補完しない |
| 記録する人 | 誰が記録したかを残す選択欄。パスワード認証や権限限制御の機能はない |

## 主な上限と保持規則

### 数値・件数の上限

| 対象 | 上限・制約 |
|---|---|
| 親子セットの階層と行数 | 完成品 → 組立品 → 部品の2階層まで。1セットあたり50行、子構成を展開した全体で500行まで |
| 必要明細の一括生成 | 1回の操作につき元を含めて20案件、合計1,000明細まで |
| 1操作あたりの保存サイズ | 競合時の元入力回収で保持できる1件あたりの上限は64KiB |
| タブ終了後の共有退避（入力回収） | 解消・取下げ済みを含めて64件、合計8MiBまで（自動削除なし） |
| 閲覧用Excel出力のセル文字数 | 1セルあたり32,767文字を超える値は先頭32,000文字に切り詰め、全文を「長い値」シートへ出力 |

### 生成した必要明細の変更規則

セットから生成した案件の必要明細に対し、「生成した必要明細の変更」を行ったときの各明細の保持・解除規則は次のとおりです。

| 操作・状態 | 数量・根拠・除外状態の扱い |
|---|---|
| 明細の除外 | 行は削除せず必要数を`0`にし、理由を履歴に残す。セット本体からその品目が削除・再追加されても除外状態を維持する |
| 台数変更の再計算／最新版への追従（手修正・除外なし） | 新しい台数または最新版の標準値（根拠は`表示の数（ラベル・パッケージ）`）へ更新する |
| 台数変更の再計算／最新版への追従（手修正・除外あり、または根拠変更済み） | 「新標準値を適用」の初期値はOFF。未選択のままなら現在の数量・根拠・除外状態を保つ。チェックを入れた明細だけ新しい標準値（ラベル値）へ更新し、除外を解除する |
| 案件独自の追加明細と最新版の品目・単位が重なった場合 | 未選択なら「案件独自」の由来・数量・根拠を保つ。「新標準値を適用」にチェックを入れると「セット由来」となり、新標準のラベル値へ変わる |
| 必要数または根拠の直接変更 | 除外されていた明細は除外が解除される |
| 必要日・元の資料・改訂のみの変更 | 除外状態や数量・根拠はそのまま保持される |
| セット本体の改訂 | 既存案件の必要明細や計算基準の版は自動では変わらない。案件ごとに「セットの最新版に追従」を実行したときだけ更新される |

### 共通消耗品・工程設定の仕様

| 対象 | 仕様 |
|---|---|
| 包装の入り数換算 | 設定時点より前に受け取った包装は入り数不明のまま残る。設定後に受け取った包装（例：1袋＝10個）は個数へ換算して集計するが、中身を数えたことにはならず「表示の数・中身未確認」として示す。入り数を変更しても過去の包装には遡及しない |
| 工程の変更・利用停止 | 「工程の完了基準の変更」は、その工程で作業の開始や中断を一度も記録していない間だけ実行できる。工程を「利用停止」にすると新規の作業開始では選べなくなるが、すでに工程内にある物の作業終了・確認の完了・次の作業へ渡す、および過去日時の作業中断は記録できる。工程は削除できない |
| v1.2.0以前の記録の読み込み | 過去の記録で使われていた工程名が登録済み工程として取り込まれ、登録時の品番・コードが`N`の場所は「次工程の場所」に指定された状態になる（製造記録のないデータには追加されない） |

## 閲覧用Excel出力のシート構成

「管理」の「閲覧用に出力（Excel・復元には使えない）」では、現在の記録を以下のワークシートに分けて出力します。

| シート名 | 出力される内容 |
|---|---|
| 説明 | 出力日時、対象版、用語の注意点、各シートの概要 |
| 集計 | 品目・単位・場所・案件・用途ごとの現在数と状態別の集計 |
| 保管単位 | すべての保管単位の現在数、根拠、場所、案件・用途、作業の状態、取り分け状態 |
| 元の記録 | 登録された操作イベントの原文記録 |
| 台帳の履歴 | 保管単位ごとの増減・移動・数え直し・訂正の履歴 |
| 供給の履歴 | 必要な数、依頼、受け取り、割り当て、材料使用推計などの供給に関する履歴 |
| 依頼 | 補充依頼・発注の状態、依頼数、未着数、到着数、使える数 |
| 工程集計 | 工程ごとの作業中・確認待ち・完成（渡す前）の数量と工程完了累計 |
| 品目の設定 | 品目ごとの単位、最小単位、包装・入り数、共通消耗品指定、補充基準の現在設定 |
| 工程の設定 | 工程の名前・完了基準・利用状態と、次工程の場所の現在設定 |
| 必要明細 | セットから生成した案件の初回の版、計算基準の版、台数、標準値、現在値、手修正の有無、由来 |
| 長い値 | 32,767文字を超える値が存在するときだけ追加され、切り詰め前の全文を格納する |

## 記録の考え方（なぜ区別するのか）

現在の数字1つだけを上書きする表計算とは異なり、このソフトでは以下の3つの区別を保つ設計をとっています。

### 1. 「数が不明」と「0」を分ける理由

中身をまだ確認していない箱に仮の`0`を入れると、「数えて空箱だと確認した」記録と見分けがつかなくなります。在庫があるのに重複発注したり、空だと思い込んで処分したりする原因になりかねません。分からない状態はそのまま`数が不明`として残し、実際に数えた時点で`数えた`へ変えてください。

### 2. 「記録上の数」と「数えた数」を分ける理由

12本登録して2本使った後の「10本」は、記録の引き算から求めた値（記録上の数）であり、今棚に10本あることを直接保証するものではありません。計算結果と実地確認（数えた）を分けて表示し、最後にいつ現物を確かめたかを追えるようにしています。実地確認で数が違ったときは「原因不明でもよい数え直し」として現在数を訂正します。架空の記録は不要です。

### 3. 予定・依頼・現物の動きを自動連動させない理由

現場では「必要になった」「注文した」「届いた」「実際に使った」や、材料の到着から作業再開までの間に時間差が生じます。補充基準を下回っただけで依頼を自動作成したり、材料が届いただけで中断中の作業を自動再開したりすると、書類上の状態と現場の現物がずれます。実際に起きた事実をそれぞれの時点で記録してください。
