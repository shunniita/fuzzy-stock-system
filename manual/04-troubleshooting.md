# 4. 困ったとき・保存と復元

[目次](README.md) · 前へ：[画面と用語](03-reference.md)

トラブルが起きたときの対処手順と、日々のバックアップ・復元・バージョン更新の手順をまとめています。

## 症状から探す

| 症状・やりたいこと | 参照する節 |
|---|---|
| これまであった記録が空に見える | [記録が見えなくなった](#記録が見えなくなった) |
| 「保存結果不明」「一部だけ保存した」「更新競合」と出た | [保存の状態を確認する](#保存の状態を確認する) |
| 競合したまま閉じたタブの元入力を取り出したい | [タブ終了後の元入力を回収する](#タブ終了後の元入力を回収する) |
| バックアップを保存したい・バックアップから戻したい | [バックアップを取り復元する](#バックアップを取り復元する) |
| 記録をExcelファイルに出力して見たい | [Excelで見たい](#excelで見たい) |
| 新しいバージョンへ更新したい・旧版のデータを確認したい | [更新する・旧版へ戻す](#update) |
| `start-local.cmd`を実行しても開けない | [起動できない](#起動できない) |
| 操作欄が切り替わらない・記録ボタンが押せない | [よくある迷い](#よくある迷い) |

## 記録が見えなくなった

**まず初期化せず、前回と同じ保存先を開いているか確認します。**

1. 前回使ったブラウザーとプロファイルと同じか確認します（InPrivateや別プロファイルは別の保存先になります）。
2. アドレス欄を確認します。`127.0.0.1`と`localhost`、ポート`4180`と`4190`はそれぞれ別の保存先として扱われます。
3. 前回と同じブラウザー・プロファイル・アドレスの組み合わせで開き直します。
4. それでも見えない場合は、保管してある復元用バックアップJSONを確認します。

アプリのフォルダーを別のPCや別フォルダーへコピーしただけでは、ブラウザー内の記録は移りません。ブラウザーの閲覧データ・サイトデータを消去する前に、必ず復元用バックアップを保存してください。

## 保存の状態を確認する

画面上部の「保存の状態」の表示に応じて、次の手順で対処します。

| 「保存の状態」の表示 | 次にすること |
|---|---|
| 保存中 | 結果が表示されるまで待つ |
| 記録していない・回答が必要・確認が必要 | 表示された理由に従って入力を直すか質問に答え、もう一度「記録する」を押す |
| 保存した | 正常に保存されている。結果を確認し、そのまま作業を続ける |
| 保存できなかった（記録されていない） | 入力欄に残った内容を確認し、同じ入力欄からもう一度「記録する」を押す |
| 一部だけ保存した | 保存済みと未保存の内訳を確認し、画面の照会と「記録し直す」で未保存分だけを処理する。最初から別操作として入れ直さない |
| 保存結果不明 | 未保存と決めつけず、「照会する」または「再試行する」を押す。照会で全単位の保存を確認できたら「保存済みとして確定する」を押す |
| 別の画面で記録が保存された | 元入力を控え、「更新競合の照合」で最新記録と比べる。照合結果を保存しただけでは元の業務操作は登録されないため、必要なら最新記録を確認したうえで入力し直す |
| 読み込めない | 表示された理由を控える。保存値を消したり初期化で上書きしたりせず、バックアップと対象版を確認する |

記録には1つのタブだけを使います。未解消の更新競合・保存結果不明・一部保存・読込不能がある間は、別の操作への切替がロックされます。画面の案内に従って解消してください。

「数が不明」「保存結果不明」「数量操作の未反映（保留）」はそれぞれ別の状態です。数が不明を0にしたり、保留中の記録を未保存だと考えて同じ操作を重ねて入力したりしないでください。

## タブ終了後の元入力を回収する

「タブ終了後の入力回収」をあらかじめ有効にしておくと、更新競合が起きたときの元入力をブラウザーの共有保存領域へ退避し、タブを閉じた後でも回収できます。明示的に有効にした保存先だけで動作します。

### 事前に有効化する手順

1. 保存結果不明や一部保存が残っていないことを確認し、復元用バックアップを保存します。
2. このアプリを開いている他のタブがあれば閉じます。
3. 行き先「管理」を開き、「タブ終了後の入力回収を有効にする」を押して確認します。
4. 「タブ終了後の入力回収：有効」と表示されたことを確かめます。

### 退避された元入力を照合・整理する手順

1. 更新競合が起きたら、「回収した元入力」の件数が増え、保存中や保存失敗の表示が出ていないことを確認します（有効化済みなら、タブやブラウザーを閉じた後でも同じアドレス・プロファイルで開き直せば一覧から参照できます）。
2. 一覧の項目を開き、「原文を控える」で内容を保存してから「この元入力を照合する」を押します。
3. 元入力と最新の記録を見比べ、照合結果・理由・確認者を記録します。この照合記録だけでは在庫数は変わらないため、必要な業務操作は最新記録を確認したうえで別途入力します。

初期化や復元より前の世代の入力、および旧版で元世代が分からない入力は参照専用です。現在の記録へ直接照合結果を付けず、原文を控えて確認します。控えを取った後に一覧から消したいときは「本文を残さず取り下げる」を選びます（再表示を防ぐ取下げ記録を残す操作であり、照合済みにはなりません）。

なお、この機能は入力途中の下書きを常時自動保存するものではありません。共有退避の上限は解消・取下げ済みを含めて64件・合計8MiBまでで、自動削除は行いません。上限超過や保存失敗が表示された場合は、タブを閉じる前に必ず画面上で原文を控えてください。

有効化後に旧版を起動して記録が書き換わると、整合性を守るため新版の保存が停止します。その場合は「管理」の「保存先の原資料を控える」で新旧の資料を保全し、初期化せずに照合してください。

## バックアップを取り復元する

### バックアップを取る

1. 「保存の状態」が「保存した」であり、保存結果不明や一部保存が残っていないことを確認します。
2. 行き先「管理」を開き、「復元用バックアップを保存」を押します。
3. ダウンロードされたJSONファイルの名前・作成日時・保存先フォルダーを確認します。
4. ブラウザーが動くPCの障害に備え、別ドライブや所定の保管先にも複製して保管します。

バックアップを自動で定期保存する機能はありません。運用開始前にバックアップの頻度と保管場所を決めてください。

### バックアップから戻す

**復元を実行すると、現在の記録はバックアップの内容で置き換わります。現在の記録も残す場合は、復元前に別名でバックアップを保存してください。**

1. 行き先「管理」を開き、「バックアップから復元」を押します。
2. 復元したいバックアップJSONファイルを選びます。
3. 確認画面で作成時刻と件数を確認します。別のファイルだった場合は「やめる」を押します。
4. 内容が正しければ「復元する」を押します。
5. 復元完了後、在庫一覧・履歴・未完了の依頼を確認します。

「閲覧用に出力」で作ったExcelファイルは復元には使えません。復元の練習は本番の業務プロファイルとは分けた試験用プロファイルで行ってください。

入力回収を有効にした保存先のバックアップには、未解消の元入力と解消・取下げ記録も含まれます。未有効の保存先へそのバックアップを復元するときは、先に「タブ終了後の入力回収を有効にする」を実行してから復元してください。

## Excelで見たい

行き先「管理」の「閲覧用に出力（Excel・復元には使えない）」を押すと、現在の在庫・履歴・設定・必要明細をまとめた`.xlsx`ファイルをダウンロードできます。出力される全11シート（および32,767文字を超える値があるときの「長い値」シート）の内訳は、[閲覧用Excel出力のシート構成](03-reference.md#閲覧用excel出力のシート構成)を参照してください。

Excelファイル上で数値を書き換えても、アプリ内の記録は変わりません。訂正はアプリ側で行ってから再出力してください。品番・コードの先頭の`0`（`0012`など）や、数式に見える呼び名（`=1+1`など）は文字列として出力します。Excelで編集して保存し直すと、先頭の`0`が消えたり数式として計算されたりすることがあるため、開いて見るだけにしてください。

## 更新する・旧版へ戻す

### 新しい版へ更新する手順

1. 旧版で「保存の状態」が「保存した」であることを確認し、「復元用バックアップを保存」で更新前のバックアップJSONを別名で保管します。旧版の展開フォルダーも消さずに残します。
2. 未確定の入力がないことを確認し、旧版のブラウザーのタブと起動用の黒い画面を閉じます。
3. 新版のZIPを旧版とは別の新しいフォルダーへ展開します（`local-settings.txt`でポート設定を変えていた場合は、同じ設定を引き継ぎます）。
4. 新版の`start-local.cmd`を起動し、前回と同じブラウザー・プロファイル・アドレスで開き、これまでの記録が表示されることを確認します。

新版で読み込めない場合は初期化せず、旧版フォルダーと更新前バックアップをそのまま保全してください。

### 版ごとの互換性と注意点

新しい版で保存した記録やバックアップは古い版では読み込めません。

| 対象 | 互換性と注意点 |
|---|---|
| v1.5.0 | 保存形式の版はv1.4.0と同じ。開封や確認待ちからのやり直し・修理を記録した記録とバックアップはv1.4.0以前では読めない |
| v1.4.0 | 保存した記録とバックアップはv1.3.0以前では読めない。更新後に初めて開くと簡単操作モードになる。今までの画面は行き先「管理」の「操作モード」で高度な操作モードを選ぶ |
| v1.3.0 | 保存した記録とバックアップはv1.2系以前では読めない。v1.2系以前の記録を開くと、使用済み工程が自動で登録済み工程になり、品番・コードが`N`の場所は「次工程への置き場」に指定される（[工程と次工程への置き場を登録する](02-guide.md#工程と次工程への置き場を登録する)を参照） |
| v1.2.0 | 保存した記録とバックアップはv1.1系以前では読めない。旧版から更新しても共通消耗品の指定や補充基準は自動追加されないため、必要な品目を[共通消耗品と補充基準を設定する](02-guide.md#consumables)で設定する |
| 入力回収を有効にした保存先 | 同じ保存先（同じポート・プロファイル）で旧版を起動したり復元したりしない。旧版が保存内容を書き換えると新版の保存が停止する |

### 旧版を別の保存先で確認する手順

更新後に、旧版と更新前バックアップの内容を安全に確認したいときは、本番の保存先と分けて別のポートで開きます。

1. 新版で「保存した」を確認し、新版のバックアップも別名で保存してから、新版のタブと起動用の黒い画面を閉じます。
2. 旧版のフォルダーにある`start-local.cmd`の隣に`local-settings.txt`を作り、`port=4190`のようにこれまで使っていないポート番号を1行で書きます（新版側の設定は変えません）。
3. 旧版の`start-local.cmd`を起動し、アドレスが指定したポート（`http://127.0.0.1:4190/`）であり、記録が空であることを確認します（既に記録がある場合は別の未使用ポートに変えます）。
4. 更新前に旧版で保存しておいたバックアップJSONを復元し、内容を確認します（新版で作ったバックアップはこの保存先へ持ち込みません）。
5. 確認が終わったら旧版のタブと黒い画面を閉じ、新版を元の設定で起動します。

## 起動できない

| 状況 | 確認と対処 |
|---|---|
| ダブルクリックしても正しく動かない | ZIPの中身を直接開いていないか確認する。ZIPを右クリックして「すべて展開」し、展開先フォルダーの`start-local.cmd`を実行する |
| ブラウザーでページを開けない | 起動用の黒い画面が開いたままになっているか、表示されたアドレスとブラウザーのアドレスが一致しているか確認する |
| 「ポートが使用中」と表示される | すでに起動しているこのソフトの黒い画面が残っていないか確認する |
| アクセス拒否（エラー10013）が出る | 端末で予約されたポートに当たっている可能性がある。黒い画面のメッセージを控え、`local-settings.txt`でのポート変更や端末設定について管理担当者へ確認する |
| 組織の制限でスクリプトが実行できない | エラー表示を控えて管理担当者へ確認する。自己判断で端末のセキュリティ制限を解除しない |

`local-settings.txt`に`port=4190`のように書いてポート番号を変えた場合、変更後のアドレスは別の保存先になります。元の記録を見るには元のアドレスで開くか、バックアップJSONを使って移行してください。

## よくある迷い

| 困っていること | 原因と対処 |
|---|---|
| 「作業の種類」を変えたのに下の入力欄が変わらない | 「作業の種類」は操作候補の絞り込み。続けて2つ目の選択欄「操作」で目的の操作を選ぶと入力欄が切り替わる |
| 操作ボタンを押しても切り替わらず下に理由が出る | 更新競合や保存結果不明などが残っている間、または保存処理中は入力保護のため切替が止まる。[保存の状態を確認する](#保存の状態を確認する)の対処を先に行う |
| 「記録する」を押しても確認を求められて保存できない | セットからの受け取りや作業開始、必要明細の生成・変更、返品の割り当てには確認チェック欄がある。内容を確認してチェックを入れてから記録する（入力値を変えてチェックが外れた場合は再プレビューしてチェックし直す） |
| 数え直しで「実際に受け取った数の扱い」の選択を求められる | 今の棚の残数だけを直すときは「実際に受け取った数は変えない（現在の残数の確認）」を選ぶ（[現物を数え直す](02-guide.md#現物を数え直す)を参照） |
| 欠品していた材料を受け取ったのに作業が「中断」のまま | 材料の受け取りと作業の再開は別の記録。作業を再開した時点で「製造・工程」の「作業の再開」を記録する |
| バーコードやQRコードが読み取れない | 「コードの入力先」で「品目」などの入力先を選び、名称・品番・コードで検索する。一致する候補の「…を適用」を押し、中身と数量は現物で確認する |
| 履歴にある「使用」を取り消せない | 「作業の開始」の材料としてまとめて記録された使用は単独では取り消せない。数量が違っていたときは、対象の保管単位全体を「数えて確認・訂正」で数え直す（[記録の間違いを直す](02-guide.md#記録の間違いを直す)を参照） |

解消しない場合は、ソフトの版・ブラウザー・行った操作名・表示されたメッセージ・期待した結果を控えてください。外部へ問い合わせる際は実案件や接続情報を送らず、架空の値で再現手順を説明します。
